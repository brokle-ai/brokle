# Repository Guidelines

## Project Structure & Module Organization
Brokle is a monorepo with a Go backend, a Next.js dashboard, and SDKs.
- `cmd/`: service entrypoints (`server`, `worker`, `migrate`).
- `internal/`: core domain logic, services, infrastructure, and workers.
- `pkg/`: shared Go utilities used across services.
- `web/`: Next.js app (`src/` features, `e2e/` Playwright tests, `public/` assets).
- `migrations/` and `seeds/`: Postgres/ClickHouse schema migrations and seed data.
- `tests/`: Go integration/infrastructure tests.
- `sdk/python` and `sdk/javascript`: language SDKs with independent tooling.

## Build, Test, and Development Commands
Use Make from the repo root for platform workflows:
- `make setup`: install dependencies/tools, start DBs, run migrations/seeds, generate docs.
- `make dev`: run backend server and worker with hot reload (`air`).
- `make dev-frontend`: run dashboard only (`web` on `:3000`).
- `make test` / `make test-unit` / `make test-integration`: Go test suites.
- `make lint` / `make fmt`: Go + frontend lint/format wrappers.
- `make build` and `make build-frontend`: production builds.

Frontend direct commands (inside `web/`): `pnpm test`, `pnpm test:coverage`, `pnpm test:e2e`.

## Coding Style & Naming Conventions
- Go: follow `gofmt`/`goimports`; lint rules are enforced via `.golangci.yml`.
- TypeScript/React: ESLint + Prettier (`web/eslint.config.mjs`, `pnpm format`).
- Python SDK: Black/isort/flake8/mypy (`sdk/python/tox.ini`).
- Naming: keep Go packages lowercase, migration files timestamp-prefixed, React component files in kebab-case, and tests adjacent to relevant modules where possible.
- Frontend imports: use feature boundaries (`@/features/[feature]`) and avoid internal deep imports across features.

## Testing Guidelines
- Go tests use `*_test.go`; run `make test` before opening PRs.
- Frontend unit/integration tests use Vitest (`*.test.ts[x]`), E2E uses Playwright (`web/e2e/*.spec.ts`).
- Python SDK uses pytest (`test_*.py`) with markers (`unit`, `integration`, `slow`).
- No strict global coverage threshold is defined; add or update tests for every behavior change.

## Commit & Pull Request Guidelines
- Follow Conventional Commit style seen in history: `feat(scope): ...`, `fix(scope): ...`, `refactor(scope): ...`, `chore: ...`.
- **Subject line only. No body.** The diff + file paths already say what changed; the subject says what it is. Long bodies (multi-paragraph rationale, bullet lists of changed files, "Wiring:" / "Binary state:" footers) bury the signal in `git log --oneline`. If genuinely load-bearing context won't fit in the subject, put it in the PR description.
- **Never add `Co-Authored-By:` trailers or any AI/LLM attribution** — commit messages read as if a human authored them.
- Keep commits focused and logically grouped.
- PRs should follow `.github/pull_request_template.md`: include summary, change type, testing performed, related issue (`Closes #...`), and screenshots for UI changes.
- Ensure local tests pass before requesting review.

## Mandatory Development Rules
- Create migrations only via CLI: `go run cmd/migrate/main.go -db <postgres|clickhouse> -name <name> create`.
- Do not create files manually under `migrations/`.
- **DDL canonical forms**: use `TIMESTAMP WITH TIME ZONE` (not `TIMESTAMPTZ`) in all Postgres DDL. sqlc's parser treats the short form as a non-`pg_catalog.*` type in `ALTER TABLE ADD COLUMN`, so the `pg_catalog.timestamptz` → `time.Time` override silently misses and the generated type falls back to `pgtype.Timestamptz`. Same principle: prefer full canonical forms in migrations (`TIMESTAMP WITHOUT TIME ZONE`, `INTEGER`, `BOOLEAN`) over shortcuts.
- **sqlc override keys use `pg_catalog.*`**: for built-in Postgres types, the override key is `pg_catalog.<type>` (e.g. `pg_catalog.numeric`, `pg_catalog.timestamptz`, `pg_catalog.timestamp`). Unprefixed forms like `numeric` or `timestamptz` are dead config — sqlc canonicalises column types to the `pg_catalog.*` form before matching, so shortened keys never match.
- **Editing sqlc.yaml — mandatory procedure**:
  1. Read the existing file; grep for the type in both prefixed and unprefixed forms.
  2. Run `make generate-sqlc` with the current config — do not assume what the output will be.
  3. Grep the generated output: `grep -c "pgtype.<Type>" internal/infrastructure/db/gen/*.go`. If count is 0, the existing config works — do not edit.
  4. If count is >0, inspect which columns leak and diagnose root cause (DDL shorthand? schema-lie nullable? codec missing?) before editing YAML.
  5. When adding an override, use the `pg_catalog.<type>` form.
  6. Every Go type mapping in sqlc.yaml must have a corresponding pgx codec registered in `internal/infrastructure/db/codecs.go` (via `pgxpool.Config.AfterConnect`). YAML tells codegen what type to emit; pgx codec tells the driver how to decode. Both must be present for runtime correctness — missing codec = compile success + scan-time panic.
- Implement backend changes using the Repository → Service → Handler flow.
- In services, construct errors with `AppError` constructors; in handlers, return errors through `response.Error()`.
- **Handler validation errors** must use `response.Error(c, appErrors.NewValidationError(message, details))` — never `response.BadRequest()`, never `response.ValidationError()` directly. Messages use Title Case (`"Invalid project ID"`), details use lowercase (`"projectId must be a valid UUID"`).
- **DELETE handlers** must return `response.NoContent(c)` (HTTP 204) — never `response.Success(c, gin.H{"message": ...})`.
- **UPDATE handlers** must return the updated entity via `response.Success(c, entity)` — never a message-only response (auth security flows like logout/password reset are the exception).
- **Handler package layout** — every package under `internal/transport/http/handlers/` has `handlers.go` (exported `Handler` struct + `New(...)` constructor + handler methods for small packages) + `types.go` (request body DTOs + response DTOs + conversion helpers). **NO `Register*Routes` functions exist anywhere** — routes are centralised in `internal/server/routes.go`'s `addRoutes` (see gotcha #39). Handlers expose only the `Handler` struct + exported method set; `internal/server/handlers.go` constructs them via `New(...)` into a `Handlers` bundle. When a package outgrows single-file (typically >700 LOC combined), split by feature: `<feature>.go` holds the feature's handler methods; `<feature>_types.go` holds its DTOs. The base `handlers.go` then holds only the struct + `New(...)`. `types.go` holds cross-feature shared DTOs. No `handlers_` filename prefix (package name already says "handlers"). References: small package — `internal/transport/http/handlers/credentials/`; feature-split — `internal/transport/http/handlers/evaluation/`; `internal/transport/http/handlers/observability/`.
- **Parameter parsing** uses inline `uuid.Parse(c.Param(...))` and `c.ShouldBindJSON(&req)` directly in handlers — no shared wrapper helpers. This follows the Go/Gin ecosystem convention (PhotoPrism, Apache Answer).
- **Auth context access** uses the `Must*` helpers on routes protected by `RequireAuth`/`RequireSDKAuth`: `middleware.MustGetUserID(c)`, `MustGetAuthContext(c)`, `MustGetTokenClaims(c)`, `MustGetProjectID(c)`, `MustGetOrganizationID(c)`, `MustGetSDKAuthContext(c)`. Panics are caught by `middleware.Recovery` → HTTP 500 on misconfiguration (missing auth middleware). The tuple-return `GetUserIDFromContext(c) (uuid.UUID, bool)` / `GetProjectID(c) (uuid.UUID, bool)` / etc. are reserved for `OptionalAuth` routes and audit-field population where unauthenticated is a legitimate runtime case. Never defensively combine `Must*` with an existence check — it defeats the invariant signal.
- **ID generation** uses `uid.New()` (UUIDv7, monotonic by spec). Do not introduce new ULID usage; `pkg/ulid` has been removed.
- **Nullable field pattern** — schema nullability drives Go type. **Category 1 (required, absence = bug)**: `NOT NULL` schema (no `DEFAULT`) + value type (`string`, `uuid.UUID`) + no `omitempty` on JSON + constructor validates. Add a `CHECK (length(x) > 0)` constraint when zero-value isn't a meaningful business state. **Category 2 (optional, absence is meaningful)**: nullable schema + pointer type (`*string`, `*uuid.UUID`) + `omitempty` on JSON + nil-check at read sites. Never use `NOT NULL DEFAULT ''` to paper over a Go type decision — that smears the two categories and masks write-path bugs. Never write `derefX` / `emptyToNilX` bridging helpers in repositories; align the domain type to the schema instead. Forbidigo rules `^deref[A-Z]` and `^emptyToNil[A-Z]` enforce this at lint time.
- **Shared cross-domain helpers** live in `internal/core/domain/shared/`. Current primitives: `shared.NilIfEmpty(s string) *string` (ingress-boundary convenience for Category-2 fields) and `shared.Ptr[T any](v T) *T` (generic, equivalent to `k8s.io/utils/ptr.To`). A helper earns a seat in `shared` only after two or more domains need it. If a helper is used by one domain, it stays in that domain.
- **slog message case — two-layer convention**. Service-layer log messages (anywhere under `internal/core/services/`) use lowercase-first to mirror the phrasing of the `*appErrors.AppError` they return on the same code path (Go convention: error strings are lowercase). Transport / worker / bootstrap layers (`internal/transport/`, `internal/workers/`, `internal/app/`, `internal/server/`, `internal/migration/`, `internal/seeder/`) use Capital-first because their messages are operational events, not error strings (e.g. `"Starting worker"`, `"Batch published to Redis streams"`). Acronyms stay uppercase (`"API key invalid"`, `"OAuth session expired"`). No Go linter enforces this — rely on reviewer discipline + the grep: `grep -rn 'logger\.\(Error\|Warn\|Info\|Debug\)("[A-Z]' internal/core/services/` should return zero hits.
- **JSON convention for response DTOs** — pointer types for optional fields use `omitempty` (matches the Kubernetes convention and the 91% established pattern in this codebase, 506/552 pointer-typed domain fields). Required fields use value types with no `omitempty`. Collection fields (slices, maps) in response DTOs do **not** use `omitempty`: `[]` means "queried, zero results" and is distinct from absent. Collections in request DTOs may use `omitempty` (absent = don't update).
- **Convention lint** — `scripts/lint-conventions.sh` runs via `make lint-conventions` and enforces DDL canonical forms (no `TIMESTAMPTZ`/`DECIMAL`/bare `INT`/`BOOL`) plus migration filename convention. Wired into `make lint`. New project-wide rules that can't be expressed in golangci-lint go here.
- **Service constructors return concrete** — `func NewXxxService(...) *XxxService { ... }`. Do NOT return a domain-level service interface from a constructor unless at least one of these is true **today**: (a) ≥2 implementations of the interface exist, (b) an actual mock/fake/stub is used in tests, (c) an external plugin boundary requires the abstraction. Orphan service interfaces (defined but failing all three criteria) are deleted on sight. Rationale: Go idiom "accept interfaces, return concrete" (Dave Cheney / Rob Pike / stdlib) — interfaces live at the consumption site, declared by the consumer for the exact methods it uses. Producer-side domain interfaces without polymorphism are cargo-cult: they add indirection, widen the surface reviewers must check, and create inconsistency when new services get added without the pre-existing interface decoration. Repository interfaces are the deliberate exception — services consume them as interfaces for the "accept interfaces" side of the idiom, and a natural multi-impl story (sqlc+pgx prod, in-memory test) exists.
- **Repository interface ISP — delete dead methods on sight.** A repository interface method with zero external callers (no caller outside `internal/core/domain/<x>/` and `internal/infrastructure/repository/<x>/`) is dead code. Same rule as orphan sentinels: delete from interface + delete the impl + flag the sqlc query as unreferenced for follow-up. Repository aggregator methods of the form `func Repos() XxxRepository` (one repo returning another) are anti-pattern in Brokle's wiring — services consume per-aggregate repositories directly via DI. Delete on sight.
- **Repository interface design — single Repository per aggregate; capability-split JIT.** The canonical pattern is one `XxxRepository` interface per aggregate in `internal/core/domain/<x>/repository.go`, with all read + write methods on it. Services depend on the full `Repository` interface; the single concrete struct in `infrastructure/repository/<x>/` satisfies it. Apply ISP *within* the interface (the dead-method delete-on-sight rule above), not by pre-emptively producing `Reader`/`Writer` sub-interfaces. **Capability-split (Reader/Writer) ONLY when a concrete read-only consumer demands it today** — e.g. a new auth-middleware enrichment service that takes only reads, or an EE/OSS plugin boundary requiring a narrowed surface. When that consumer appears, split the *one* aggregate it touches in the same PR. Don't preemptively split: Brokle is pre-production, no consumer narrows to `Reader` yet, and the split is pure declaration cost (extra type names, extra doc comments, no realised benefit). Reference precedent: every aggregate in `internal/core/domain/{auth,user,prompt,organization,billing,observability,evaluation,…}/repository.go` is single-interface today; this matches Gitea's package-as-aggregate idiom (no interfaces, but the same "one surface per aggregate" principle) and rejects the SigNoz Getter/Setter/Handler split as a YAGNI violation for a codebase without polymorphic consumers. The 2026-04-26 lessons-learned entry has the full revert rationale.
- **Domain DTO file organization — Gitea feature-grouped, fat-dump rule.** Domain files follow the Gitea feature-grouped pattern: one file per coherent feature/aggregate (e.g. `dataset.go`, `experiment.go`, `session.go`, `apikey.go`). A file is a "fat dump" — and gets split — when ANY of these holds: (a) it mixes ≥3 unrelated aggregates (e.g. sessions + API keys + RBAC); (b) it exceeds ~500 LoC carrying CRUD types for ≥3 separate features; (c) its name (e.g. `entities.go`) doesn't describe its actual contents. Cross-feature shared DTOs go in `dtos.go`. Repository interfaces in `repository.go` (or per-feature siblings when the file would otherwise exceed ~150 LoC). Per the error-taxonomy unification, domain packages ship **zero `errors.go` files** — `scripts/lint-conventions.sh` blocks reintroduction. Reference precedent in this repo: handler-layer feature split at `internal/transport/http/handlers/evaluation/{score_config,dataset,experiment,…}.go`. Anti-precedent (deleted): the pre-2026-04-26 `evaluation/entities.go` (958 LoC mixing 6 aggregates) and `auth/auth.go` (703 LoC mixing sessions + API keys + RBAC).
- **Error taxonomy — single `pkg/errors.Error` type + Reason-driven wire (Grafana/k8s/Boundary pattern)**:
  - **One package, one type, one alias.** `pkg/errors` is the only error package; `*pkg/errors.Error` is the only error type. Import as `appErrors "brokle/pkg/errors"` everywhere (domain, repo, service, handler, middleware, worker). No `derrors`, no `*AppError`, no per-domain sentinels — those were all retired in the 2026-04-28 unification.
  - **`*Error{Reason}` carries everything.** Closed `Reason` enum: **`ReasonUnspecified` is iota=0 placeholder** (proto3 / k8s `StatusReasonUnknown` / gRPC `codes.Unknown` convention — NEVER set on a real error; reserving iota=0 prevents the "&Error{} matches Internal" sentinel collision); real reasons start at iota=1: `ReasonInternal`, `ReasonNotFound`, `ReasonAlreadyExists`, `ReasonInvalidInput`, `ReasonBadRequest`, `ReasonUnauthenticated`, `ReasonPermissionDenied`, `ReasonConflict`, `ReasonRateLimit`, `ReasonPaymentRequired`, `ReasonUpstream`, `ReasonUnavailable`, `ReasonNotImplemented`. Plus `Resource` string, optional `Message`/`Details`/`Code`/`Param`/`Errors []ErrorDetail`, `Op` (log-only), `Cause` (Unwrap chain). Predicates: `appErrors.As(err) *Error`, `appErrors.IsReason(err, ReasonX)`, `appErrors.IsNotFound(err)`, `IsAlreadyExists(err)`, `IsConflict(err)`, `IsUniqueViolation(err)` (pgx UNIQUE classifier). **`Is` method has no wildcard semantics** — `errors.Is(err, &Error{Reason: ReasonX})` matches if-and-only-if the receiver's Reason is X (and Resource/Code match when set on target). For "is this any *Error" use `appErrors.As(err) != nil` — k8s `apierrors`, pgx, Boundary all use this pattern; wildcard-inside-Is is non-idiomatic in Go.
  - **Constructor signatures** (read `pkg/errors/errors.go` for the full list). Three groups by signature shape:
    - **Default-message-usable** (single positional, message via `WithMessage` opt when needed): `NotFound(resource, opts...)`, `AlreadyExists(resource, opts...)`, `Unavailable(resource, opts...)`, `PaymentRequired(opts...)`. Defaults like "X not found" / "X already exists" work for the majority of callsites.
    - **Message-required** (message is a positional arg): `Conflict(resource, message, opts...)`, `PermissionDenied(resource, message, opts...)`, `NotImplemented(resource, message, opts...)`, `InvalidParam(field, message, opts...)`, `Unauthenticated(message, opts...)`, `BadRequest(message, opts...)`, `RateLimit(message, opts...)`, `Upstream(resource, cause, opts...)` (cause-positional), `Internal(message, cause, opts...)`. The empirical rule: when 100% of historical callsites set the same option, promote it to positional.
    - **Multi-field validator output**: `InvalidFields(details []ErrorDetail, opts...)` — the only HTTP-422 constructor that takes a slice. Used by the `pkg/request` validator boundary when go-playground/validator returns N field errors in one struct decode. Sets `error.errors[]` on the wire and uses `details[0].Location` as `error.param` for single-param SDK consumers (Stripe convention). Don't construct `*Error` via struct literal at the validator boundary — use this constructor (k8s `apierrors.NewInvalid` precedent).
    - **Deleted on 2026-04-28**: `InvalidInput(resource, opts...)` was the original HTTP-422 catch-all. It conflated entity-level with field-level rejection. Replaced by `InvalidParam` (single field) + `InvalidFields` (multi-field). Lint rule in `scripts/lint-conventions.sh` blocks reintroduction. The 4 remaining "entity-level" sites that lived on `InvalidInput("entity", WithMessage(...))` were reclassified: `signup` XOR → `BadRequest`; incomplete OAuth/login sessions → `Conflict("oauth_session"|"login_session", ...)`; UUID parse failures → `InvalidParam`.
    - **Options**: `WithMessage(s)`, `WithDetails(s)`, `WithCode(s)`, `WithParam(s)`, `WithFieldErrors([]ErrorDetail)`, `WithOp(s)`, `WithCause(err)`.
  - **HTTP 422 — pick the right constructor by shape.** Three options, no overlap:
    - `InvalidParam("session_id", "must be a valid UUID")` — single named input field couldn't parse or violates its constraint. Sets `error.param` for SDK consumers (Stripe convention). 90%+ of HTTP-422 sites.
    - `InvalidFields(details, opts...)` — multi-field validator output (go-playground/validator returned N field errors in one struct decode). Sets `error.errors[]` (k8s convention) and `error.param = details[0].Location` for single-param SDKs. Currently used at `pkg/request.classifyValidationError` only; future gRPC interceptor / CLI flag parser will reuse.
    - For "this whole entity failed validation" with no specific field — that case turned out to not exist in the codebase. Audit found every "entity-level" site was actually a state-machine problem (`Conflict`), a request-shape problem (`BadRequest`), or a single-field parse (`InvalidParam`). If you think you need a generic 422 with no field, you're probably reaching for `Conflict` or `BadRequest`.
    - **`InvalidInput(...)` constructor was deleted** on 2026-04-28 because it conflated all three cases. Lint blocks reintroduction. Don't construct `*Error` via struct literal at the validator boundary — use `InvalidFields` (k8s `apierrors.NewInvalid` precedent: named constructor per shape, struct literals only for in-package internal mutation).
    - **XOR / "exactly-one-of" / cross-field constraints use `BadRequest(message)` naming both branches**, never synthesise a `param` for a non-existent field. Production precedent (Stripe `source` XOR `customer`, OpenAI `messages` XOR `prompt`, Google `oneof`, k8s, Boundary, Vault, MS Graph): 6 of 7 surveyed APIs return HTTP 400 with a top-level message; **zero** use the `errors[]`-array shape for XOR. The score-linkage rule (`trace_id+span_id` OR `experiment_id`) and auth-signup rule (`organization_name` OR `invitation_token`) both use `BadRequest`. The `InvalidParam` first arg MUST be a real wire field that exists on the request body — synthetic field names like `"linkage"` are banned by `scripts/lint-conventions.sh`.
  - **Repository layer** is the SINGLE translation point: `db.IsNoRows(err)` → `appErrors.NotFound("<resource>")`; `appErrors.IsUniqueViolation(err)` → `appErrors.AlreadyExists("<resource>")`; everything else → `appErrors.Internal("...", err)`. Always `WithOp("repo.<domain>.<method>")`. NEVER use `fmt.Errorf("...: %w", domain.ErrXxx)` — that pattern was the source of the Phase-6 404→500 regression.
  - **Service layer** PASSES THROUGH (`return s.repo.GetByID(ctx, id)` is correct because the repo error self-describes its wire shape). Services may construct `*Error` directly for service-layer-only conditions (validation, business-rule rejection) using the same constructors.
  - **Transport layer** (`pkg/response.WriteError` for HTTP, future gRPC interceptor): single-branch `buildAPIError` — `appErrors.As(err) != nil` → `Reason.HTTPStatus()` + `Reason.HTTPType()` + `Error.PublicMessage()` + optional Code/Details/Param/Errors; everything else → opaque 500. Locked by `pkg/response/error_shape_test.go`.
  - **Framework boundary**: `appErrors.FromHTTPStatus(status, message, cause...) *Error` synthesises an *Error from a bare HTTP status (chi method-not-allowed 405, decoder 422, body-size 413, …). Class fallback: any unmapped 4xx → `ReasonBadRequest`, any unmapped 5xx → `ReasonInternal`. Eliminates the regression class where unmapped statuses leaked into the server-fault category.
  - **Domain packages ship ZERO `errors.go` files.** All failure classification flows through `pkg/errors` constructors at the repository boundary + predicates at the consumer (`appErrors.NotFound("xxx")` + `appErrors.IsNotFound(err)` / `IsAlreadyExists` / `IsConflict` / `IsReason(err, ReasonX)`). The 11 historical `internal/core/domain/*/errors.go` files (auth, billing, comment, credentials, dashboard, evaluation, observability, organization, playground, prompt, user) were deleted on 2026-04-30 — the residue of the pre-unification architecture. `scripts/lint-conventions.sh` blocks reintroduction structurally. Verified production precedent: k8s `apimachinery` ships zero domain sentinels (single `apierrors.IsNotFound` across 40+ resource types); CockroachDB / HashiCorp Boundary / Vault same. Gitea's typed-struct pattern (`ErrRepoNotExist struct { ID int64 }`) is the outlier; Brokle's `*Error{Reason, Resource, Op, Cause}` already carries those structured fields without per-domain types.
  - **Migration status**: complete as of 2026-04-28. The earlier two-package `derrors` + `appErrors` experiment (2026-04-27) was folded into a single `pkg/errors` package on the same day. Legacy `*AppError` struct, `New*Error` constructors, `ErrorType` enum, `Wrap*` helpers, `IsAppError` / `AsAppError` predicates — all deleted. See 2026-04-28 Lessons Learned for the unification arc.
- **Routes are centralised in `internal/server/routes.go addRoutes`** — Mat Ryer + SigNoz pattern (see gotcha #39). Handler packages do NOT export route registration; `internal/server/handlers.go NewHandlers` constructs every `Handler` instance via its package's `New(...)`, bundles them into the `Handlers` struct, and `addRoutes` wires `r.Get/Post/...("/...", h.Domain.Method)` directly. NEVER reintroduce per-package `RegisterRoutes` helpers — single-source-of-truth for the URL surface is the whole point of the Phase-5 refactor.
- **chi v5 routes are registered WITHOUT trailing slashes.** `r.Get("/api/v1/users/me", h.X)` — no slash. chi treats `/foo` and `/foo/` as distinct routes (no normalisation by default), and the entire frontend + SDK ecosystem uses no-slash REST convention (Stripe, GitHub, OpenAI). Two exceptions: (1) `r.Get("/", h)` index handlers inside `r.Route("/foo/{id}", ...)` are trailing-slash-safe automatically — chi's `Mount` registers stubs at both `/foo/{id}` and `/foo/{id}/` (verified in `mux.go Mount`). (2) Do NOT add `chimw.StripSlashes` middleware as a "defence in depth" layer — it silently masks future regressions where someone re-adds a trailing-slash route, defeating the discipline.
- **Authorization at the route layer via `r.With(middleware.RequirePermission(...))`** — every org-scoped or project-scoped route in `routes.go` is decorated with `r.With(middleware.RequirePermission(authD, "<resource>:<action>"))`. Handlers do NOT call `memberSvc.IsMember(...)` or `CheckUserPermission(...)` themselves — middleware enforced once is the single layer; data-layer `WHERE organization_id = ?` filters are the future second layer. RBAC follows Langfuse's two-tier OVERRIDE semantics via `ProjectMemberService.CheckUserPermissionsInScope(ctx, userID, orgID, projectID, perms)` — see gotcha #39.
- **Run `make reseed` after editing `seeds/*.yaml`** — the seeder is NOT auto-invoked by `make dev`. After editing `seeds/permissions.yaml` or `seeds/roles.yaml`, run `make reseed` (alias for `make seed`; idempotent + transactional via `seedRoles → UpdateRolePermissions → DELETE+INSERT in tx`). Skipping this step leaves dev databases with stale `role_permissions` rows, and every route guarded by a newly-added permission 403s for existing users until reseed (the Phase-6 regression that blocked dashboard load). Custom org-scoped roles created by admins are NEVER touched by the seeder — its `GetByNameAndScope` lookup filters `scope_id IS NULL` (system templates only). Build-time guard: `internal/seeder/coverage_test.go` asserts every permission in `routes.go RequirePermission(...)` decorations exists in `seeds/permissions.yaml` — drift fails `go test`.
- **Research before re-architect** — when a non-trivial design decision (new architectural pattern, framework feature usage, wire-contract change, error-shape change) lands on the table, **launch a research agent first** to verify the chosen approach against 5+ production peers in the same shape (LLM observability tier: Anthropic, OpenAI, Langfuse, Helicone; payments/AI: Stripe; orgs/teams: GitHub, Linear, Auth0). The Brokle-specific evidence pattern: when a reviewer pushes for a defensive-feeling addition (StripSlashes middleware, body-side request_id, wrap-everything error types, double-check membership in handler), check whether 5+ peers actually do it before adopting. If zero peers do, the "preserve the previous behaviour" or "add for safety" framing is preserving an anti-pattern. Documented in 2026-04-26 / 2026-04-20 Lessons Learned. **Generalisable rule: an in-house pre-prod consumer base means most defensive-shape arguments are speculative; resist the migration cost until a real workflow demands it.**

## HTTP Framework — Chi v5

**Stack (locked, do not re-litigate)**: chi v5 router + `pkg/request` (JSON decode + `go-playground/validator/v10`) + `pkg/response` (error envelope + success helpers). Two surfaces — `/v1/*` (SDK plane, X-API-Key auth) and `/api/v1/*` (dashboard plane, cookie+JWT auth). Middleware: `go-chi/httprate` + `httprate-redis`, `jub0bs/cors`, Go 1.25 `http.CrossOriginProtection`. Huma, humachi, and every OpenAPI-related piece were removed in the chi-only migration; the legacy gin/swaggo/gorilla stack is also gone.

**Server bootstrap** (`internal/server/server.go` `New`): (1) `chi.NewRouter()`. (2) `installGlobalMiddleware(mux, deps)` — chi requires middleware before routes. (3) `addRoutes(mux, deps)` — domain handlers + group-scoped middleware (auth, rate limit, CORS, CSRF). (4) `newProbeDispatcher(mux, ready, healthDeps)` wraps the chi mux with an outer `http.ServeMux` for `/livez`, `/readyz`, `/healthz`, `/metrics` — those paths bypass chi and its middleware entirely. The `http.Server` serves the dispatcher, NOT the bare chi mux.

**Handler patterns:**
- Handler signature: `func(w http.ResponseWriter, r *http.Request)`. Mount on chi with `r.Get/Post/Put/Patch/Delete` inside the per-domain `RegisterRoutes`.
- Path params: `request.URLParamUUID(r, "id")` / `request.URLParamInt(r, "n")` / `chi.URLParam(r, "slug")` for non-typed values. Both return a typed `*AppError` on parse failure.
- Query params: `request.QueryInt(r, "limit", 50)` / `request.QueryOptionalBool(r, "has_error")` / `request.QueryOptionalUUID(r, "org_id")` / `request.QueryPagination(r)`. Optional helpers return `*T` (nil = absent).
- Body: `var body fooBody; if err := request.DecodeJSON(r, &body); err != nil { response.WriteError(w, err); return }`. `DecodeJSON` enforces `http.MaxBytesReader` (1 MiB), `DisallowUnknownFields`, trailing-data rejection, and runs `go-playground/validator/v10` struct tags. Validator errors propagate as `AppError.Errors[]` with per-field `{Location, Message, Value}`.
- Responses: `response.Success(w, body)` (200), `response.Created(w, body)` (201), `response.NoContent(w)` (204), `response.JSON(w, status, body)` (escape hatch), `response.WriteError(w, err)`.
- Auth context: `httpctx.MustGetUserID(ctx)` / `MustGetAuthContext(ctx)` / `MustGetTokenClaims(ctx)` / `MustGetProjectID(ctx)` / `MustGetOrganizationID(ctx)` / `MustGetSDKAuthContext(ctx)`. Tuple-return forms (`httpctx.UserID(ctx) (uuid.UUID, bool)`, etc.) reserved for `OptionalAuth` routes.
- Client IP + User-Agent: `httpctx.ClientIP(ctx)` / `httpctx.UserAgent(ctx)` — populated by `middleware.RequestMetadata` in the global chain.
- Cookies: `http.SetCookie(w, &http.Cookie{...})` (stdlib). Reference helpers: `handlers/auth/cookies.go` `setAuthCookies` / `clearAuthCookies`.
- Redirects: `http.Redirect(w, r, url, http.StatusFound)` (stdlib). OAuth callbacks never return a Go error — errors are encoded as query params on the signin redirect.
- Per-domain `RegisterRoutes(r chi.Router, services..., logger *slog.Logger)` function. Called exactly once from `internal/server/routes.go` inside the appropriate chi group (sdkPublic / sdkAuth / dashPublic / dashAuth).

**Validation bodies** use `validate:"..."` struct tags from `go-playground/validator/v10`. Common tags: `required`, `min=N`, `max=N`, `oneof=a b c`, `email`, `url`, `uuid`, `omitempty`, `dive`. Field paths in the returned `Errors[]` use the `json` tag via `RegisterTagNameFunc` — clients see `body.api_key`, not `body.APIKey`.

**Handler tests use plain `httptest`** — `chi.NewRouter()` + `handler.RegisterRoutes(r, ...)` + `httptest.NewRequest` + `httptest.NewRecorder`. Reference: `internal/transport/http/handlers/credentials/handlers_test.go`, `internal/transport/http/handlers/organization/handlers_test.go`.

**AppError shape** (`pkg/errors/errors.go`) is the OpenAI/Stripe shape — closed `ErrorType` enum (`TypeInvalidRequest`, `TypeValidation`, `TypeAuthentication`, etc.) + open `Code` string field + `Param` field for single-field error hints + `Errors []ErrorDetail` for per-field validation diagnostics. HTTP status is a pure function of `Type` via `ErrorType.HTTPStatus()`. Framework-boundary translation (HTTP status → AppError Type) lives at `appErrors.FromHTTPStatus(status, msg, errs...)`.

**Stub-only domain signal**: if a handler package is 90% TODO responses, or if no `RegisterRoutes` call exists in `server/routes.go`, DELETE the package. Precedents: `handlers/logs/`, `handlers/analytics/`, `handlers/enterprise/`, `handlers/websocket/`. Git history preserves them if a real need arrives.

## Known Gotchas

### Backend

1. **No OpenAPI spec is emitted by the server.** The chi-only migration dropped the Huma-provided OpenAPI surface. SDKs (Python + JS) are hand-written, not generated; the frontend uses raw `fetch` without codegen. If a future need arises, hand-write `openapi.yaml` and serve it with Scalar or Redoc — do not reintroduce runtime spec generation.
2. **Migration files must use the CLI** — `go run cmd/migrate/main.go -db <postgres|clickhouse> -name <name> create`. Manual files in `migrations/` are silently ignored by the framework.
3. **`json.RawMessage` fields in domain entities** — Several domain types use `json.RawMessage` for provider-agnostic JSON (`observability.Score.Metadata`, `prompt.ModelConfig.Tools/ToolChoice/ResponseFormat`). Always use DTO conversion in handlers; never serialize domain entities with `json.RawMessage` fields directly via `response.Success()`.
4. **Error import alias** — Services and handlers import `appErrors "brokle/pkg/errors"` (not `errors`). Handlers use `response.Error(c, appErrors.NewValidationError(msg, details))` for validation failures and `response.Error(c, err)` to forward service errors. The canonical validation pattern is: `response.Error(c, appErrors.NewValidationError("Invalid project ID", "projectId must be a valid UUID"))`.
5. **Transaction scoping** — PostgreSQL repositories take `*db.TxManager`; methods call `r.tm.Queries(ctx)` for sqlc-generated queries and `r.tm.DB(ctx)` for squirrel-built dynamic queries. Transactions propagate through `ctx` (set by `TxManager.WithinTransaction(ctx, fn)`), so passing the same context through nested service calls keeps them in the same tx. ClickHouse repositories use `clickhouse.Conn` directly (raw driver) — transaction scoping does not apply there.
6. **Dual auth context keys** — SDK routes (`/v1/*`) set the SDK auth context via `httpctx.WithSDKAuthContext` / `WithAPIKeyID` / `WithProjectID` / `WithOrganizationID`. Dashboard routes (`/api/v1/*`) set the dashboard auth context via `httpctx.WithAuthContext` / `WithUserID` / `WithTokenClaims`. Calling `httpctx.MustGetUserID(ctx)` in an SDK handler or `MustGetSDKAuthContext(ctx)` in a dashboard handler panics (caught by Recovery → 500). Always match the getter to the route group. Keys themselves are unexported empty-struct singletons; the only public surface is the `With*` setters + `MustGet*`/tuple-return getters in `internal/transport/http/httpctx/`.
7. **Dual ports** — HTTP API runs on port **8080**, gRPC (OTLP telemetry ingestion) runs on port **4317**. They are independent servers.
8. **Enterprise build tag** — `-tags="enterprise"` gates SSO, RBAC, and compliance features in `internal/ee/`. OSS builds have stubs. Don't assume EE features exist without the tag.
9. **Background email pattern** — All `emailSender.Send()` calls triggered by HTTP requests must use a detached context: `go func() { ctx, cancel := context.WithTimeout(context.Background(), 30*time.Second); defer cancel(); ... }()`. Never use the request context for async work that must complete after the handler returns.
10. **Worker DLQ semantics** — `telemetry_stream_consumer.go` uses `ErrMovedToDLQ` to signal "safe to ACK even though processing failed" (data preserved in DLQ). Non-DLQ errors leave messages pending for retry. New workers consuming from Redis streams must follow this pattern: ACK on success OR `ErrMovedToDLQ`, leave pending on other errors.
11. **Route middleware order matters** — The global chain is installed by `server.installGlobalMiddleware` in `internal/server/middleware.go` BEFORE `addRoutes` mounts any route (chi's `Mux.Use` panics once any route is registered — see Transport gotcha #31). Order: `chimw.RequestID` → `chimw.RealIP` → `middleware.RequestMetadata` → `middleware.RequestLogger` → `middleware.Recoverer` → `middleware.Metrics`, plus CORS + CSRF scoped to `/api/v1/*` via `pathPrefix`. Health + `/metrics` endpoints do NOT live on the chi mux — they're served by an outer `http.ServeMux` dispatcher (`server.newProbeDispatcher`, see Transport gotcha #32) that bypasses this chain entirely. Per-group middleware (inside `addRoutes`): sdkPublic = `LimitByIP` + `LimitByKeyPrefix`; sdkAuth = `RequireSDKAuth` + `LimitByAPIKey`; dashPublic = `LimitByIP`; dashAuth = `RequireAuth` + `LimitByUser`.
12. **Config validation is mode-specific** — `config.go` skips certain validations when `APP_MODE=worker` (e.g., `JWT_SECRET` not required). If promoting a worker to server, all server-mode validations must pass.
13. **Auth context storage types** — `httpctx.WithUserID` / `WithProjectID` / `WithOrganizationID` all store `uuid.UUID` **by value**. Only `httpctx.WithAPIKeyID` stores `*uuid.UUID` because `AuthContext.APIKeyID` is legitimately nullable (session-based auth contexts have no API key). Don't mix value/pointer forms — `MustGetProjectID(ctx)` etc. strictly type-assert `uuid.UUID` and will panic on a pointer.
14. **No platform-admin concept** — All roles in `seeds/roles.yaml` are `scope_type: "organization"` (owner, admin, developer, viewer). There is no platform-wide admin role; the `annotation.RoleAdmin` constant is an unrelated per-queue reviewer role. If you think you need platform-admin endpoints (token revocation, incident response, etc.), stop and design the role/permission model first — don't scaffold unreachable guarded routes.
15. **Nested-actor hydration for list endpoints** — `Invitation.Inviter *InviterRef` and `Invitation.Role *RoleRef` are loaded via LEFT JOIN in list-path repository methods (`GetPendingInvitations`, `GetByEmail`), populated alongside the invitation row in one query. Handlers read `inv.Inviter` / `inv.Role` directly — no per-row `userService.GetUser` lookups, no nil-deref on the nullable `InvitedByID` FK. Single-row reads (`GetByID`, `GetByTokenHash`) leave `Inviter`/`Role` nil; callers at those call sites guard explicitly. Pattern mirrors Gitea's `Comment.Poster *User` / `LoadPoster` and GitHub/GitLab's nested-actor JSON shape. Apply the same shape if you add other actor/author references (don't flatten `xxx_email` / `xxx_name` fields at the top level).

### Frontend

16. **Frontend `ignoreBuildErrors: true`** — `web/next.config.ts` disables TypeScript build errors. Type errors won't fail the build; run `pnpm type-check` locally.
17. **Standalone output mode** — Frontend builds as a standalone Node.js app (`output: 'standalone'`), not static files. Docker uses `node .next/standalone`.
18. **API client auth is cookie-based** — `withCredentials: true` is required for httpOnly cookies. CSRF tokens are extracted from cookies and added to mutation requests (POST/PUT/PATCH/DELETE) only, not GET. Auth token refresh is owned by the Zustand auth store, not the API client.
19. **Context headers are opt-in** — API client methods require explicit flags (`includeOrgContext`, `includeProjectContext`) to attach `X-Org-ID` / `X-Project-ID` headers. They are not sent by default.
20. **Feature module structure** — Each feature in `web/src/features/` follows: `api/`, `components/`, `hooks/`, `stores/`, `types/`, `utils/`. Import across features only via `@/features/[feature]`, never into internal subdirectories.
21. **One `proxy.ts`, in `src/`** — Next.js 16 accepts `proxy.ts` at the project root OR inside `src/`; if both exist, the root file silently shadows the `src/` one (no warning, no build error). Brokle uses the `src/` layout, so `web/src/proxy.ts` is canonical. NEVER create `web/proxy.ts` at the root. Same rule applies to other Next.js file-conventions (`middleware.ts`, `instrumentation.ts`) — `src/` only.
22. **Proxy is presence-only, backend is the authority** — `web/src/proxy.ts` checks cookie *presence* (`req.cookies.has('access_token') || .has('refresh_token')`) and redirects to `/signin` if absent. Do NOT JWT-decode the cookie locally (couples middleware to backend signing scheme, bypasses revocation/blacklist) and do NOT check only `access_token` (an expired access token + valid refresh token must reach the dashboard so the API client's 401 interceptor can reactively refresh). Cookie validity is the Go backend's job; proxy is the optimistic edge guard.
23. **Wire contract is Stripe/OpenAI-style — NO envelope on success** — Success (2xx) bodies are the raw resource directly (`{"id":"prj_123","name":"..."}`), NOT wrapped in `{success:true, data:{...}, meta:{...}}`. List endpoints inline pagination: `{"data":[...], "pagination":{page,limit,total,total_pages,has_next,has_prev}}`. Error (4xx/5xx) bodies are `{"error":{"type":"...","message":"...","code"?:"...","details"?:"...","param"?:"...","errors"?:[...]}}`. HTTP status is the ONLY success/failure signal (per RFC 9110 §15). **`code` is OPTIONAL** — set explicitly via `WithCode(...)` only when SDK consumers should branch on a sub-classification beyond `type` (Stripe `card_declined`, OpenAI `unknown_parameter`); NEVER let it default to `string(Type)`. The old `CodeOrType` fallback was removed because every site emitted noise like `code:"authentication_error"` mirroring `type` — defeating the entire point of having two fields. Use the named codes in `pkg/errors/codes.go` when meaningful. Request IDs are surfaced via the `X-Request-Id` response header (chi `RequestID` middleware), NOT the body — matches Stripe / OpenAI / GitHub / Twilio / Cloudflare / Helicone (9 of 14 surveyed APIs are header-only; only Anthropic / MS Graph / AWS S3 duplicate, and that's an SSE-streaming / SOAP-era accommodation Brokle doesn't need). Frontend reads it via `response.headers.get('x-request-id')` in `web-vite/src/lib/api/errors.ts`. Enforced across three write sites by `pkg/response/error_shape_test.go` — `AppError.MarshalJSON`, `ErrorResponse` direct marshal, and chi-middleware `WriteError` produce byte-identical envelope bytes. Never reintroduce `success`, `data`, or `meta` wrappers; the frontend, Python SDK (`brokle/_http/client.py`), and JS SDK (`src/_http/client.ts`) all assume raw shapes.

### SDKs (JavaScript & Python)

21. **SDKs are git submodules** — `sdk/javascript/` and `sdk/python/` are independent repos mounted as submodules. Commits inside them don't appear in the main repo's `git diff` — only the submodule pointer changes. Use `cd sdk/javascript && git status` to inspect SDK changes. Run `git submodule update --init` after cloning.
22. **First-write-wins singleton** — Both SDKs use a global singleton pattern. JS uses `Symbol.for('brokle')` on `globalThis`; Python uses a module-level `_client` variable. First `BrokleClient()` / `Brokle()` call wins — subsequent calls with different configs are ignored. Use `setClient()` / `set_client()` to explicitly override.
23. **Provider wrappers are optional peer deps** — JS: `wrapOpenAI`, `wrapAnthropic`, etc. require the provider SDK installed but won't fail at import — only at wrapper call. Python: same pattern via `brokle.wrappers`. Never bundle provider SDKs as direct dependencies.
24. **JS: Proxy pattern for wrappers** — `wrapOpenAI()` returns a recursive `Proxy` that intercepts method calls without modifying the original client. Don't extend or subclass provider clients; wrap them.
25. **JS: Multi-entry tsup build** — 11 entry points (core + 10 integrations) with separate `.d.ts` files. Import from sub-paths: `import { wrapOpenAI } from 'brokle/openai'`, not from root `'brokle'`.
26. **JS: Node >= 20 required** — Relies on `AsyncLocalStorage` for context scoping. No browser or Node 18 support without polyfills.
27. **Python: Lazy module loading** — `brokle/__init__.py` uses `__getattr__` + `importlib` for 150+ exports. `from brokle import *` won't work. Import specific names.
28. **Python: `BROKLE_` env var prefix** — All env vars are uppercase with `BROKLE_` prefix: `BROKLE_API_KEY`, `BROKLE_BASE_URL`, `BROKLE_ENABLED`. Lowercase variants don't work.
29. **Python: No atexit flush** — SDK doesn't register process exit handlers. Serverless/CLI apps must call `brokle.flush()` before process exit or traces are lost.
30. **Python: mypy selectively disabled** — `pyproject.toml` has `ignore_errors = true` overrides for wrappers, config, and client modules. Don't assume full type safety in those areas.
30a. **Shared `_http/` client module per SDK** — Both SDKs centralise REST transport in one module: Python `sdk/python/brokle/_http/client.py` (`SyncHTTPClient` / `AsyncHTTPClient`) and JS `sdk/javascript/src/_http/client.ts` (`BrokleHttpClient`). Resource managers (scores, datasets, prompts, experiments, query, annotations) call `http.get/post/patch/delete` and get the raw resource back — no per-manager envelope unwrap, no `unwrap_response` / `extractData` helpers. Error paths raise typed exceptions matched to HTTP status (`AuthenticationError` 401/403, `NotFoundError` 404, `ValidationError` 422, `RateLimitError` 429, `ServerError` 5xx, `BrokleError` fallback). Do NOT reintroduce per-manager fetch wrappers, envelope-unwrap helpers, or status-code-to-error mappers — the shared client owns both.
30b. **Error taxonomy: two-axis model, never wrap HTTP errors into module-local types.** Every major production SDK (Stripe `_error.py`, OpenAI `_exceptions.py`, Anthropic `_exceptions.py`, AWS v3 `@smithy/smithy-client`, Azure Core `azure.core.exceptions`, Google `google.api_core.exceptions`, Octokit `@octokit/request-error`, Twilio `RestException`) ships **one** shared error hierarchy and raises from it at every resource. Brokle follows the same shape: `BrokleError` + `AuthenticationError` / `ValidationError` / `NotFoundError` / `RateLimitError` / `ServerError` / `ConnectionError` (shared, in `_http/errors.py` / `src/errors.ts`). Module-local error types exist ONLY for axis-2 semantics HTTP status cannot express (Python: `InvalidFilterError`; JS: `InvalidFilterError`, `QueueNotFoundError`, `ItemNotFoundError`, `ItemLockedError`, `NoItemsAvailableError`, `ScorerError`) and they **extend** the shared family rather than wrapping it — e.g. `InvalidFilterError extends ValidationError`, so `except ValidationError` and `except InvalidFilterError` both match. NEVER introduce catch-all wrappers like `QueryAPIError`/`ScoreError`/`AnnotationError(error.message)` that swallow the shared subclass — they break `isinstance(e, AuthenticationError)` / `e instanceof AuthenticationError` at the call site and produce the N×M class explosion industry explicitly avoids. Parse failures on 2xx bodies (malformed JSON, `from_dict` shape mismatch) wrap as `BrokleError("Failed to parse …", original_error=e)` — typed family, preserves the chain, still one catch clause. `classifyError` helpers (see `annotations/manager.ts:77-98` for the reference) translate ONLY for axis-2 distinctions (queue vs item 404, lock contention, empty-queue state), never for blanket re-typing.

### Transport (chi v5)

31. **chi `Mux.Use` must precede every route registration.** `go-chi/chi/v5/mux.go:100-104` panics `"all middlewares must be defined before routes on a mux"` on the first `Use` after any `Get`/`Post`/`Handle`/`MethodFunc`. `installGlobalMiddleware` in `internal/server/middleware.go` is the one authoritative place to call top-level `r.Use`; it runs BEFORE `addRoutes`. NEVER call `r.Use(...)` on the top-level mux inside `addRoutes` — sub-routers via `r.Route` / `r.Group` are fine because they have independent middleware stacks.
32. **Probe + `/metrics` paths bypass chi entirely.** `internal/server/health.go`'s `newProbeDispatcher` returns an outer `http.ServeMux` (Go 1.22+ pattern routing) that serves `/livez`, `/readyz`, `/healthz`, `/metrics` from raw handlers and forwards everything else to the chi mux. Purpose: kubelet probes (~6/min × pod) and Prometheus scrapes don't dominate the request logger or inflate `http_requests_total`. Pattern verified at Loki, Consul, Vault, k8s apiserver. **Do NOT add API routes to the dispatcher** — it exists solely for ops-plane bypass. New ops-plane paths (`/debug/pprof/*`) are the only legitimate additions.
33. **Rate-limiting: per-IP for unauth, per-principal for authed — never layer.** Industry pattern (GitHub, Stripe, OpenAI, Anthropic, Cloudflare WAF) scopes authenticated rate limits to the authenticated principal (user ID, API key ID, organization), not to IP. IP-based buckets apply ONLY to pre-auth routes (`/api/v1/auth/login`, `/signup`, `/forgot-password`, `/oauth/callback`, `/refresh`, `/v1/auth/validate-key`, `/website/contact`). Layering `LimitByIP` on top of `LimitByUser` on the same authenticated request is the NAT/BFF/SSR bug class: any shared-egress client (corporate NAT, CGNAT, mobile carriers, Next.js SSR pods, serverless) collapses all users into one bucket and cross-throttles legitimate traffic. Brokle's wiring: `installGlobalMiddleware` sets CORS/CSRF/RequestMetadata/RealIP/RequestID at the mux — NO rate limiting; `addRoutes` mounts `LimitByIP` on the pre-auth chi groups (`sdkPublic`, `dashPublic`) and `LimitByUser` / `LimitByAPIKey` on the authed groups (`dashAuth`, `sdkAuth`). Do NOT re-add mux-level `LimitByIP` — it reintroduces the cross-user throttling regression. Edge-layer flood defence (Cloudflare, ingress `limit_req`) is where network-level abuse mitigation belongs, not the app layer.
34. **Body DTO validation via `go-playground/validator/v10`.** Request bodies declare their constraints with `validate:"..."` struct tags; `pkg/request.DecodeJSON` runs the shared validator instance after decode. The `Errors[]` array on `AppError` carries per-field diagnostics (`body.api_key`, `body.items[3].tags`) — the JSON tag name is used via `RegisterTagNameFunc` so clients never see Go field names. NEVER reimplement request-body validation inline; call `request.DecodeJSON`.
35. **One `r.Route` per URL prefix per chi tree.** Only `r.Route(pattern, fn)` (and `r.Mount`) calls chi's internal `Mount`; Mount checks `findPattern(pattern+"*")` / `findPattern(pattern+"/*")` and panics at boot if either already exists. Two sibling `chi.Group` sub-routers share their parent mux's routing tree — middleware stacks are independent, the trie is not — so two `r.Route("/api/v1/auth", ...)` calls from sibling groups collide. Direct registrations (`r.Post("/api/v1/auth/login", h)`, `r.Get(...)`) write concrete leaves to the trie, never call Mount, and coexist fine across sibling groups. For mixed-posture domains (auth: public `/login` + protected `/me`), keep the two Register functions and have each register concrete paths instead of wrapping in `r.Route`. When two domains legitimately share a URL prefix (`/api/v1/projects/{projectId}/*`), give each a distinct deeper prefix as sibling Mounts (`/scores`, `/sessions`, `/datasets`, `/experiments`) — chi's radix trie routes static-deeper before wildcard-shallower so they coexist. `scripts/lint-conventions.sh` enforces prefix uniqueness; `internal/server/routes_test.go` boots the full tree to catch registration-time collisions. See 2026-04-24 Lessons Learned.
37. **Scaffolded-but-unreachable handler packages get deleted, not preserved.** `handlers/enterprise/` (630 LoC, never wired), `handlers/websocket/` (463 LoC, never wired), `handlers/logs/`, `handlers/analytics/` have all been deleted on this principle. Signal: the package has no caller in `internal/app/providers.go` (no `NewHandler()` invocation), or the caller is behind a build tag never built. Git history preserves them if a real need ever arrives. Same rule from gotcha #14 (no platform-admin) — don't scaffold routes guarded by permissions no one holds.
38. **Routes are centralised in `internal/server/routes.go addRoutes`** — Mat Ryer pattern (the 2024 Grafana Labs article that defines the modern Go HTTP-services shape) + SigNoz's `aH.Signoz.Handlers.X` bundle pattern + Brokle's pre-Huma gin shape. `addRoutes` is THE place to find any URL, its middleware chain, its permission requirement, and its handler — single source of truth, ~500 LoC, one file. Per-package `Register*Routes` helpers were deleted across all 18 handler packages in Phase 5; handlers now expose only the `Handler` struct + `New(...)` constructor + exported method set, and `internal/server/handlers.go NewHandlers` constructs the `Handlers` bundle. NEVER reintroduce per-package route registration — it splits the URL surface across files, hides the middleware chain, and prevents the `r.With(middleware.RequirePermission(...))` per-route decoration the RBAC layer relies on (gotcha #39). The lint script `scripts/lint-conventions.sh` enforces no `^func Register` definitions exist under `internal/transport/http/handlers/`. Routes-test `internal/server/routes_test.go` boots `addRoutes(chi.NewRouter(), stubDeps)` against typed-nil services and a `recover()` assertion — catches registration-time NPEs and chi prefix collisions (gotcha #35) at the boot boundary. See 2026-04-26 Lessons Learned.
39. **RBAC is two-tier with SCOPE-PARTITIONED hybrid semantics.** `organization_members` is the base tier; `project_members` is an OPTIONAL per-project override. The resolver `internal/infrastructure/db/queries/project_member.sql ListUserEffectivePermissionsInScope` applies different composition rules per `permissions.scope_level`. Three structural rules: (1) **active-org-membership precondition** — both branches require an active `organization_members` row in the org; a stale `project_members` row alone grants ZERO permissions, closing the privilege-retention bug after `RemoveMember`; (2) **org-scoped permissions** (`p.scope_level = 'organization'`, e.g. `members:*`, `billing:*`, `organizations:*`) resolve against the ORG ROLE ONLY — project membership is irrelevant. A project role granting an org-scoped permission is silently inert. This honors the org-rooted concept: shared verbs like `members:remove` decorate project-member-management routes but resolve via the user's org role. (3) **project-scoped permissions** (`p.scope_level = 'project'`, e.g. `traces:*`, `datasets:*`) follow OVERRIDE — if a `project_members` row exists, its role REPLACES the org role's project projection. Supports both ELEVATE (org viewer → project admin) AND RESTRICT (org admin → project viewer for sensitive carve-outs) for project-scoped capabilities. `ProjectMemberService.CheckUserPermissionsInScope(ctx, userID, orgID, projectID, perms)` is the single resolver — pass `uuid.Nil` as projectID to skip the project layer. Mounted into the request path via `middleware.RequirePermission` / `RequireAnyPermission` / `RequireAllPermissions` reading `httpctx.MustGetOrganizationID(ctx)` + `httpctx.ProjectID(ctx)`. `RequireProjectAccess` middleware does a 2-step check: `Project.GetProject(...)` → `OrgMember.IsMember(userID, project.OrganizationID)` → pin BOTH `projectID` AND `orgID` into ctx. The named codes catalogue at `pkg/errors/codes.go` is the registry of meaningful sub-codes; `WithCode(...)` opts an error into one. **Role assignment validates scope at the service layer** (`validateProjectAssignableRole` in `project_member_service.go`): rejects system-scoped roles, rejects org-custom roles whose `scope_id` doesn't match the project's org (cross-tenant role injection), rejects project-scoped roles whose `scope_id` doesn't match the project. NEVER call `OrgMember.CheckUserPermissions(...)` (the org-agnostic, multi-org-fan-out variant) from middleware — it leaks permissions across orgs. The org-agnostic method exists only for the `/api/v1/rbac/users/{userId}/permissions/check` catalog endpoint. Pattern verified against Langfuse's actual implementation (`langfuse/web/src/features/rbac/`): scope-partitioned `hasOrganizationAccess` / `hasProjectAccess` entry points. The earlier "MAX semantics" (2026-04-27) AND "wholesale OVERRIDE" (2026-04-27 → 2026-04-30 evening) wordings in this codebase were both mis-citations — Langfuse never used either; it's always been scope-partitioned. See 2026-04-30 (project-rbac-resolver) Lessons Learned.
40. **chi v5 routes register WITHOUT trailing slashes.** `r.Get("/api/v1/users/me", h)` — no slash. chi treats `/foo` and `/foo/` as distinct routes (no implicit normalisation), and the entire ecosystem (frontend, JS SDK, Python SDK, Stripe, GitHub, OpenAI) uses no-slash REST convention. The Phase-5-recovery sweep stripped 92 trailing slashes from `routes.go`; future routes follow the same rule. Two carve-outs: (1) `r.Get("/", h)` inside `r.Route("/foo/{id}", ...)` is trailing-slash-safe automatically — chi's `Mount` (`mux.go`) explicitly registers stubs at both `/foo/{id}` and `/foo/{id}/`, so both request paths reach the subrouter's `/` handler; this is the only case where keeping the slash is correct. (2) Do NOT add `chimw.StripSlashes` middleware as a "defence in depth" layer — it silently masks future regressions where someone re-adds a trailing-slash route. CLAUDE.md "no fallbacks for scenarios that can't happen" rule applies; trailing-slash callers from the frontend/SDKs don't exist, and external curl users get a 404 they can fix. NEVER use `chimw.RedirectSlashes` either — its 301 redirect silently converts POST→GET and drops the request body (RFC 7231 §6.4.2).
41. **Tenancy is in the URL — never in body, never in query.** For routes mounted under `r.Route("/api/v1/organizations/{orgId}/...", ...)` (or `/projects/{projectId}/...`), the orgID/projectID is pinned into ctx by `RequireOrganizationAccess` / `RequireProjectAccess` AFTER membership validation. Handlers MUST read it via `httpctx.MustGetOrganizationID(ctx)` / `MustGetProjectID(ctx)` — NEVER from `c.Body.OrganizationID`, `r.URL.Query().Get("organization_id")`, or any equivalent. Three structural rules enforce this: (1) request DTOs MUST NOT contain a tenancy field — `pkg/request.DecodeJSON` enforces `DisallowUnknownFields`, so a client sending `organization_id` in the body gets a 422 with the unknown-field message; (2) on org-scoped list/create endpoints, explicitly reject `?organization_id=` query params with 422 ("Unknown query parameter — organization_id is set by the URL path"); (3) handlers MUST NOT re-call `memberSvc.IsMember(...)` after middleware enforced — it's defense-in-depth at the wrong layer (middleware + future repo-side `WHERE organization_id = ?` filter is the correct two layers; two checks at the same layer share fate). Pattern verified at Stripe Connect (`Stripe-Account` header), GitHub (`POST /orgs/{org}/repos` body has no `org`), PostHog (path-only), Auth0 (subdomain), Supabase (subdomain), Jira (path xor body never both). The opposite — URL-says-A but body-says-B writes go to B — is OWASP API1:2023 BOLA + parameter tampering. Cross-tenant list ("all my projects across orgs") is a SEPARATE endpoint (GitHub `/user/repos` shape), never a silent fan-out behind an org-scoped route. See 2026-04-26 Lessons Learned.

## Lessons Learned

- 2026-04-26: Repository capability-segregation refactor — **proposed, executed across 3 domains, then reverted in the same session.** Phase 1 of the standardisation sweep (ISP cleanup, ~109 dead methods deleted across 12 fat repositories) shipped clean and stays in. Phase 2 split user, prompt, and auth into Reader/Writer sub-interfaces composed back into `Repository` — modelled on SigNoz's `pkg/modules/<x>/` Getter/Setter/Handler pattern. After it landed, reviewer pressure-tested with the right question: *what concrete consumer narrows to `Reader`?* Answer: zero. Every service constructor still took the composed `Repository`. The split was pure declaration cost — extra type names, extra doc comments, extra reviewer surface, no realised benefit. Reverted user, prompt, and auth back to single-interface-per-aggregate. Generalisable rule (now codified above): apply ISP *within* the interface (delete-dead-methods-on-sight), not via pre-emptive producer-side capability subtypes. Capability-split JIT — when a concrete read-only consumer appears, split the one aggregate it touches in the same PR. Don't split for a hypothetical future consumer; in a pre-production codebase the future consumer may never arrive, and Go's structural typing makes the JIT split a 5-minute mechanical change when it does. Process meta-lesson: when a refactor lands and you can't answer "which caller benefits *today*?" with a concrete file path, the refactor is speculative. Same failure mode as the 2026-04-24 service-interface sweep — abstraction without polymorphism is cargo-cult regardless of which layer it lives on. Web research (Martin Fowler YAGNI, Three Dots Labs CQRS guidance, Dave Cheney "accept interfaces") was unanimous: defer architectural complexity for pre-production codebases until a concrete consumer forces it. The reference doc at `claudedocs/REPOSITORY_STANDARDIZATION_PLAN.md` captures the full Phase 1 outcome + the JIT-split rule + the "deliberately reverted" status of Phase 2.

- 2026-04-24: Codebase-wide service-interface sweep, grounded in the Go idiom "accept interfaces, return concrete" (Dave Cheney, Rob Pike, stdlib). Audit surfaced 51 domain-level service interfaces across 13 domain packages; of those, 43 were returned from their constructor and 0 had any polymorphism story — zero mocks, zero alternate implementations, zero external plugin boundaries. All orphan. Earlier in the same session I'd moved in the *opposite* direction twice (created a new domain interface for `ScoreAnalyticsService` because a boundary-crossing service "should" have one; created `pkg/db/pgerrors` to classify pg errors at the repo boundary which required importing HTTP-coupled types into the domain layer). Both reverted once the ecosystem data showed Brokle is a web-app-shape codebase where Gitea/Prometheus/stdlib patterns fit — concrete returns, consumer-side interfaces only when polymorphism actually exists. The rule now codified as a Mandatory Development Rule: constructors return `*XxxService`; domain-level service interfaces require ≥2 impls **today**, a real mock, or an external plugin boundary. Generalisable process lesson: when introducing an abstraction, first check the ecosystem for precedent in codebases with the same shape, not just the theoretically cleanest design. A single-impl no-mock interface is indirection pretending to be architecture; in a DDD codebase without polymorphism it's the same cargo-cult a misread of clean-architecture tutorials causes elsewhere. Repository interfaces are the legitimate exception — they satisfy criterion (a) via the service-consumption pattern (service accepts `xxxRepository`, prod uses sqlc+pgx, tests can stub). Also kept from the same session arc: goroutine-ctx detachment fix in `prompt/execution_service.go:146` (streaming LLM calls now use `context.WithTimeout(context.Background(), 5*time.Minute)` per gotcha #9); handler cleanup (listAPIKeysResponse → types.go, projectId UUID-parse normalisation); Gitea-pattern service-boundary error translation (repos wrap UNIQUE violations to `domain.ErrAlreadyExists` via `appErrors.IsUniqueViolation(err)`, services translate to `NewConflictError`).

The chi `_examples/rest` pattern (one `r.Route` with inner `r.Group`) is for **single-function** route-tree construction and doesn't apply to split-registration cases; checking the simpler primitive (direct `r.Post` on a shared tree) FIRST would have produced a two-line diff instead of a ~20-file refactor plan. Also added `scripts/lint-conventions.sh` rule flagging any `r.Route("/api/v1/...")` prefix that appears in more than one handler file (catches future collisions at lint, before boot). Generalisable rule (both technical and process): when decomposing routes by middleware posture leads to two `r.Route` calls at the same prefix, drop the `r.Route` — concrete-path registration handles sibling-group coexistence natively; don't reach for consolidation or new abstractions before checking whether the simpler chi primitive already covers the case.

Generalisable rule: single-maintainer framework dependencies through the request path are a serviceable risk only while pre-production; pay the migration cost before external consumers lock you in. Removed 2,600 LoC net (Huma + OpenAPI scaffolding deleted > request/validator helpers added). The `pkg/request.DecodeJSON` pattern (MaxBytesReader + DisallowUnknownFields + trailing-data reject + tag-driven validator) is the canonical Go HTTP decoder (Alex Edwards / Brandur references baked in) — every handler now speaks the same body-safety dialect.

- 2026-04-17: Defensive handler-level auth checks (`if !exists { 401 }` after `middleware.GetXxx(c)`) mask programming errors and add boilerplate. The idiomatic Go fix is the `Must*` convention from `regexp.MustCompile` / `template.Must`: handlers trust the middleware invariant and call `middleware.MustGetUserID(c)` etc. directly; a misconfigured route (missing `RequireAuth`) now panics → `middleware.Recovery` → HTTP 500 with stack trace, surfacing the bug instead of silently returning a misleading 401. - 2026-04-17: Bulk `sed` replacements on SQL migrations require replacing longer patterns first (`VARCHAR(26)` before `CHAR(26)`), otherwise `CHAR(26)` inside `VARCHAR(26)` matches first and produces invalid types like `VARUUID`. Same applies to frontend: `sed 's/ulid/uuid/g'` on TS files corrupted `import('ulid')` → `import('uuid')` (package didn't exist) and `ulid()` → `uuid()` (wrong API). Always verify dynamic imports and runtime calls after bulk renames.

Everything else is `uuid.Parse()`, `uuid.Nil`, `id.String()` directly. Removed `uid.Parse()`, `uid.MustParse()`, `uid.IsZero()`, `uid.Nil` after recognizing they were trivial pass-throughs.

Kept for months until an audit found it. CLAUDE.md rule: "don't design for hypothetical future requirements." Git history preserves the implementation if a real need arrives.

- 2026-04-19: AppError redesign — closed `ErrorType` enum + open `Code` field (OpenAI/Stripe shape) replaces the old single `AppErrorType` that did double duty as both type and code. The original gin error path had a status→code map with a `default → INTERNAL_ERROR` branch, which silently misclassified every framework-emitted 4xx (405/406/408/413/415/416/417/451) as a server fault. The fix is structural: HTTP status is now a pure function of `Type` via `ErrorType.HTTPStatus()`, framework errors arrive via `appErrors.FromHTTPStatus(status, msg, errs...)` which uses an explicit map + RFC 9110 class fallback (4xx→`TypeInvalidRequest`, 5xx→`TypeAPIError`). The misclassification bug class is now structurally impossible. Sentinel test `TestFromHTTPStatusClassFallback` locks the invariant.

- 2026-04-20: Option B wire-contract migration — dropped the `{success, data, meta}` envelope across backend + frontend + Python SDK + JS SDK in favour of Stripe/OpenAI shape (raw resource on success, `{error:{...}}` on error, HTTP status as the signal, `X-Request-Id` in header). Signal that triggered it: the frontend `extractData` threw on every Huma success response because Huma emits raw bodies while the JS client still asserted `responseData.success !== undefined`. Rather than patch the asymmetry, unified all four surfaces. Key decisions: (1) no backward-compat shim — there are no production users yet, so a clean cutover beats a dual-shape adapter; (2) byte-identical invariant across three backend write sites (`AppError.MarshalJSON`, `statusError` via `NewError`, chi-middleware `WriteError`) locked by `pkg/response/error_shape_test.go`; (3) handler-returned `*AppError` bypasses `huma.NewError` (Huma's `errors.As` path at `huma.go:1100-1105` marshals the error directly), so both `AppError.MarshalJSON` and the envelope factory must produce the same bytes independently; (4) both SDKs collapsed their per-manager HTTP helpers into one `_http/client.{py,ts}` module with typed-exception error handling (~700 LoC of dead helper code deleted). The generalisable rule: when a wire contract splits (success raw, error enveloped, or vice versa), unify in one direction — pick the side with more industry precedent (Stripe/OpenAI > internal envelope conventions) and cut over all consumers simultaneously. Half-envelope states are a bug class, not a migration state.
- 2026-04-20: SDK error-hierarchy audit — a reviewer asked me to restore module-local `QueryAPIError` / `ScoreError` wrapping so transport failures from `query.*` and `scores.*` managers came back as the module type instead of the shared `BrokleError` subclass. Web research across nine major production SDKs (Stripe, OpenAI, Anthropic, AWS v3, Azure Core, Google Cloud, Octokit, Twilio, Apollo) showed the unanimous pattern is the opposite: one shared hierarchy + per-module types ONLY for semantics HTTP status cannot express, with those types EXTENDING the shared family rather than wrapping it. Deleted `QueryAPIError`, `QueryError`, `ScoreError` and the blanket-wrap branch in `annotations/manager.ts` `classifyError`. `InvalidFilterError` now extends shared `ValidationError` (so `except ValidationError` catches filter-syntax rejection too). Generalisable rule captured in gotcha #30b: when a reviewer pushes wrap-everything, first check whether any first-party SDK ships that shape — if zero do, the "preserve the previous behaviour" request is preserving an anti-pattern and the right answer is a principled pushback with the evidence, not silent compliance.
- 2026-04-20: Rate-limit layering audit — the `/api/v1/*` stack was carrying both a mux-level `LimitByIP` and a Huma-group-level `LimitByUser` on authenticated traffic. Phase-2 DAL SSR fetches exposed the bug: all users' `/api/v1/users/me` hits from the shared Next.js Node pod collapsed into one IP bucket, cross-throttling legitimate users at normal dashboard concurrency. The fix was structural, not a forward-XFF workaround — authenticated buckets are now per-principal only, matching GitHub (per-user post-auth, per-IP pre-auth), Stripe (per-account), OpenAI/Anthropic (per-org), and Cloudflare's WAF best-practice guidance. `LimitByIP` moved from the mux onto the pre-auth Huma groups (`dashPublic`, `sdkPublic`) where it belongs; authed groups run with `LimitByUser` / `LimitByAPIKey` alone. Generalisable rule: never layer an IP counter on top of a principal counter on the same request — NAT, CGNAT, corporate egress, and BFF/SSR all collapse the IP axis, and the stack fails on legitimate traffic before it fails on abusers. Forwarding `X-Forwarded-For` from the SSR hop is now a logging/audit correctness fix (populates `httpctx.ClientIP` with the real user IP), not a rate-limit requirement.
- 2026-04-20: Probe-bypass-middleware is the Go ops-plane convention, verified at Loki (`pkg/util/server/server.go` `DoNotLogURL` regex), Consul (`agent/http.go` `wrap()` allowlist), Vault (`vault/http/handler.go`), and the Kubernetes apiserver (`pkg/endpoints/filters/longrunning.go`). Brokle's `newProbeDispatcher` uses an outer `http.ServeMux` (Go 1.22+ pattern routing) wrapping the chi mux — the same shape. This replaces an earlier attempt that registered `/livez`, `/readyz`, `/healthz`, `/metrics` ON the chi mux "before global middleware" to keep probes silent — that design is incompatible with chi's "middleware before routes" invariant and panics at boot. The wrapper pattern keeps chi's middleware contract intact AND gives ops-plane paths a clean bypass. Separate-admin-port (OpenTelemetry Collector, SigNoz) is the minority variant reserved for deployments with distinct probe/API trust boundaries — not applicable to a single-port k8s Service like Brokle's today, but reversible to later in ~20 LoC.
- 2026-04-27: Error-translation re-architecture — eliminated the "service forgot to translate" bug class. Symptom: `RequireProjectAccess` middleware swap from `CanUserAccessProject` → `GetProject` in Phase 6 dropped the sentinel→AppError translation, turning every well-formed-but-missing project ID into 500 instead of 404 across `/api/v1/projects/{projectId}/*`. Surface fix (Phase A): per-method `errors.Is(err, ErrProjectNotFound) → appErrors.NewNotFoundError("project")` translation in `GetProject` + `GetProjectBySlug`. **But that's a workaround for the bug CLASS** — the discipline fails the moment any service writes a one-line `return s.repo.X(...)` passthrough, of which the codebase has dozens. Web research across **k8s apimachinery `apierrors.StatusError`, Grafana `errutil`, HashiCorp Boundary `internal/errors`, CockroachDB `cockroachdb/errors`** — every major Go project with multi-transport (HTTP + gRPC + CLI) ships errors-with-reason-at-source: a transport-agnostic `Reason` enum carried by the domain error, read mechanically by each transport adapter. Per-method translation has zero major OSS production adopters; it shows up only in "clean architecture" sample apps. Architectural fix (Phase B): introduced `internal/core/domain/shared/errors` — `*Error{Reason, Resource, Op, Cause}` with constructors (`derrors.NotFound("project")`, `derrors.AlreadyExists("user")`, `derrors.Internal("get x", cause)`) and `Reason.HTTPStatus()` / `Reason.HTTPType()` pure functions. `pkg/response.WriteError buildAPIError` extended with a third branch: `derrors.As(err) != nil` → wire-identical envelope to the equivalent AppError (locked by `TestErrorShape_DomainErrorMatchesAppError` byte-comparison test). Project domain migrated end-to-end as the reference implementation (repo wraps `pgx.ErrNoRows` → `derrors.NotFound("project")` ONCE; service is now a correct passthrough; per-domain sentinels `ErrProjectNotFound` + `ErrProjectAlreadyExists` deleted). Result: the bug class is structurally impossible for migrated paths — a service writing `return s.repo.GetByID(ctx, id)` IS correct because the repo error self-describes its wire shape. Other domains (user, auth, billing, observability, etc.) migrate piecemeal; legacy "service translates" continues to work until each domain crosses over. **Generalisable rule (added to Mandatory Development Rules): when a discipline-based pattern fails in production, check whether 5+ major Go OSS projects ship the discipline OR a structural alternative — if zero ship the discipline, the discipline is the bug. The k8s/Grafana/Boundary/Cockroach pattern is the industry default; per-method translation never made it past sample-app tutorials.**
- 2026-04-27: RBAC + membership edge-case fixes — three behavioural regressions and one mis-cited model. (1) **`ProjectMemberService.AddMember` accepted any role**: no scope_type / scope_id check, so an admin could attach a system role OR an org-B custom role to an org-A project (privilege escalation). Fixed by adding `validateProjectAssignableRole` — rejects scope=system, rejects org-custom roles whose scope_id != project's org, rejects project-scoped roles whose scope_id != project. Pattern verified at GitHub teams (org-bound), Snowflake (`GRANT DATABASE ROLE` rejects cross-DB), Microsoft Entra (`directoryScopeId`), Auth0 (tenant-bound API token). (2) **Stale `project_members` after `RemoveMember`**: `OrganizationMemberService.RemoveMember` only soft-deleted the org_members row; the user's project_members survived and the permission resolver UNION'd them in (privilege retention). Fixed in SQL — `ListUserEffectivePermissionsInScope` now requires an active org_members row in BOTH branches; a stale project_members row alone grants zero. Picked query-time gate over eager cascade because it preserves audit trail and re-invitation UX (Snowflake / Langfuse implicit model; GitHub eagerly cascades inherited team membership but keeps direct grants). (3) **Stale `role_permissions` after YAML expansion (65→86 perms)** blocked existing dev users from any route guarded by a new perm. The seeder's `seedRoles → UpdateRolePermissions` already does atomic delete+reinsert (`role_repository.go:207-224`), but the `make dev` flow needs to ensure boot-time reseed runs (Kubernetes pattern: *"At each start-up, the API server updates default cluster roles with any missing permissions"*). Documented + smoke test added that asserts every `RequirePermission(authD, "...")` permission in `routes.go` is present in `seeds/permissions.yaml` — build-time drift guard. (4) **Mis-cited "Langfuse MAX semantics"** — the code, gotcha #39, and 2026-04-26 entry all claimed Brokle implemented "Langfuse MAX/UNION semantics", but the actual Langfuse RBAC docs (langfuse.com/docs/administration/rbac) describe **OVERRIDE semantics** (project role REPLACES org role when present, not UNION). Brokle was implementing UNION (project role can only elevate). For an LLM observability platform where some projects may carry data even org admins shouldn't see (the load-bearing restrict case), override is the right model — strictly more expressive. SQL rewritten to override in the same change. **Generalisable rule: when citing a vendor's model as architectural precedent, verify against their actual docs/source — the vendor name is a load-bearing reference future contributors trust. The cost of getting it wrong is they implement the wrong semantics for years before someone re-reads the source.**
- 2026-04-30 (project-rbac): Two P1 regressions on the project-membership / RBAC surface, both surfaced by reviewer audit after the cascade-and-cleanup work. (1) **`projects:read` guard on single-resource GET broke custom roles.** `internal/server/routes.go:341` decorated `GET /api/v1/projects/{projectId}` with `RequirePermission("projects:read")`, and the frontend's URL context resolver (`web/src/lib/context/url-context-manager.ts:148`) calls this endpoint to validate project context for *every* dashboard navigation. On 403 it drops `projectId` from context, so a custom role with `datasets:read` (or any other project-scoped permission) but without `projects:read` couldn't open ANY project page even though downstream feature routes would authorize the user on their own merits. Web research surveyed 8 production APIs — split ~5/3: GitHub `metadata: read` (auto-included with any other repo permission via the "floor scope" mechanic), GitLab `read_api`, Auth0 `read:clients`, Langfuse `projects:read` enforce explicit floor permission; Linear `GET /workspaces/{id}`, Stripe Connect `GET /accounts/{id}` with `Stripe-Account` header, PostHog `GET /api/projects/{id}` treat membership as sufficient for identity primitives. GitHub's pattern is "permission gate done right" — the floor scope is structurally auto-included with any other repo-scoped permission, preventing the failure mode. Brokle does NOT implement that auto-include mechanic, and has no custom-role-creation UI today, so building it before the workflow exists is premature complexity. **Decision: drop `projects:read` from the single-resource GET only** (Linear/Stripe-Connect/PostHog model). Other single-project routes (`PUT`/`DELETE`/`Archive`/`Unarchive`) keep permission guards (state changes are gated). Org-scoped LIST keeps `projects:read` (deciding which projects exist IS gated metadata). ## Pre-Production Review Charter

External code reviewers (Codex, Claude) default to production-grade hardening — rollback safety, backward compat, defensive layering, migration immutability. In pre-prod Brokle most of those concerns are speculative cost. Apply this charter when invoking reviewers AND when triaging their output.

**Constraints to state up-front in review prompts:**
- Pre-production: no users, no production data, dev DBs are resettable.
- No backward-compatibility requirement on wire shape, schema, or APIs.
- Prefer **schema edits** over forward+down migration pairs; prefer **deletion** over deprecation; prefer **structural fixes** (lint guards, invariants) over discipline-based recipes.
- Defensive-shape suggestions (StripSlashes, body-side request_id, wrap-everything error types, double-check membership in handler) require 5+ production-peer precedent before adoption — see the "Research before re-architect" rule.

**Triage by severity, not by count:**
- Act on **P1** correctness/security/data-loss only.
- Defer **P2/P3** unless the fix is cheap AND structural (e.g., adds a lint guard that prevents the bug class).
- If three review rounds attack the same file, **stop fixing the file and ask whether the file should exist** (2026-04-30 status-column lesson).

**Generalisable rule:** an in-house pre-prod consumer base means most defensive-shape arguments are speculative; resist the migration cost until a real workflow demands it. Reviewer feedback in tight loops on the same file is a category-error smell — the file probably shouldn't exist in the shape the review keeps attacking.
